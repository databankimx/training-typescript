# Ch28 - Complexity

A program can be correct and still be too slow. A search that checks every item is fine for ten values and painful for ten million. Complexity is the study of how the work grows as the input grows, and it gives you a way to compare two methods before you run either one. This chapter introduces the notation, then applies it to searching and sorting, where the difference between methods is largest.

The search and sort lessons have visualizers: animations that show each algorithm working through the same values. Press **Visualize** on those steps to open the animation in its own window.

## What you'll learn

1. How to count the work a loop does, and how that count grows with the input.
2. How linear and binary search differ, and why sorted data makes binary search possible.
3. How the quadratic sorts compare, and why their counts are fixed or depend on the data.
4. How quicksort, merge sort, heap sort, and shell sort reduce the work, and what each one trades for it.

The chapter ends with a summary, and a homework exercise.
